# 盘后决策卡

## 职责

本文件说明盘后决策卡的定位、入口、规则来源和已知限制。它是独立于 ReviewRun 正式对象链的轻量入口，只回答四个问题：**当前市场情绪、明天能不能买、买什么、买多少**。

## 与 ReviewRun 正式链的关系

| 维度 | ReviewRun 正式链 | 盘后决策卡 |
| --- | --- | --- |
| 目标 | 可追溯、不可变的正式 publication | 当日可用的决策结论 |
| 对象 | RunManifest/EvidenceBundle/RevisionBundle/ActionSet | 无，单次运行直接产出 Markdown |
| 确认 | 两次完整对象确认 + 哈希链 | 一次运行，无需确认 |
| 当前状态 | 生产出全缺口报告，尚未真实验收 | 已跑通真实数据 |

决策卡**不写 `data/review_run.sqlite`、不创建 publication、不进入 `reports/daily/`**，因此它不会与正式链产生同名产物冲突，也不能被表述为正式复盘。

> 定位已确认（2026-10-09）：决策卡作为**独立决策入口**保留，不并入正式对象链。它与 `PROJECT_RULES.md` 红线 2 的关系是：决策卡不被表述为"平行正式流程"——其产物不进 `reports/daily/`、不写 `review_run.sqlite`、不产生 publication。**若后续验证其结论长期可用，再考虑提升为主链**；那需要正式修改红线 2，不在此处自行变更。

## 入口

```powershell
.\.venv\Scripts\python.exe -m stock_review.decision --date 2026-10-09
```

可选参数：`--lookback-days`（情绪序列回看交易日数，默认 5，仅采集模式生效）、`--report-dir`、`--data-dir`、`--stdout`、`--from-snapshot`。

输出：

| 产物 | 默认位置 |
| --- | --- |
| 决策卡（Markdown） | `reports/decision/<trade-date>.md` |
| 输入与结论快照（JSON） | `data/decision/<trade-date>.json` |

### 从既有快照重渲染

规则或渲染变更后，可回看已归档交易日「按当前规则会长什么样」，不需要重新采集：

```powershell
.\.venv\Scripts\python.exe -m stock_review.decision --from-snapshot data\decision\2026-10-13.json --report-dir reports\decision\preview --data-dir data\decision\preview
```

- `--from-snapshot` 只读回 `data/decision/<trade-date>.json` 里已冻结的输入事实，**不调用任何外部数据源**。它与下面「禁止给历史日期补跑」并不冲突：那条红线针对的是重新请求实时快照接口（涨跌家数、板块榜），而重渲染复用的是当日已落盘的事实——事实层逐字不变，只有规则层重算。
- 缺省沿用快照记录的 `generated_at`，因此重渲染产物与归档卡只在规则相关部分产生差异，可直接 `diff` 核对。
- `--date` 在该模式下可省略；若同时给出，必须与快照交易日一致，否则终止。
- 默认输出目录会**覆盖**该日归档产物；只想预览时，配合 `--report-dir` / `--data-dir` 指向其他目录。

## 通达信连接器接入

通达信数据走 MCP 通道，只能由 Agent 调用，无法被 Python 进程直接请求。因此接入方式是**快照解耦**：

1. Agent 通过通达信连接器采集当日事实，落成 `data/decision/tdx/<trade-date>.json`；
2. 决策卡运行时用 `src/stock_review/decision/tdx_snapshot.py` 读取该快照，作为一等输入并入判定与渲染。

快照缺失或 JSON 非法时一律视为「本次未接入通达信」，返回 `None`，**绝不用默认值或臆造数据冒充通达信证据**。

自校验（每个交易日采集后必须执行）：

```powershell
.\.venv\Scripts\python.exe -m stock_review.decision.tdx_snapshot --date 2026-10-09
```

它回答快照是否合法、各字段采到几条、有无条目被静默跳过；`ok=false` 时必须先修好快照再重跑决策卡。逐日采集的固定步骤见 [`DECISION_TDX_COLLECTION.md`](DECISION_TDX_COLLECTION.md)。

| 快照字段 | 用途 | 落地位置 |
| --- | --- | --- |
| `code_lookup` | 名称 → 代码解析，补全板块领涨股代码 | 第五节候选对象 |
| `board_quotes` | 概念/行业板块当日行情，补全 akshare 缺失的概念维度 | 第四节板块主线 |
| `stock_themes` | 个股涨停主题与原因揭秘 | 第五节「涨停逻辑（通达信）」 |
| `news` | 当日资讯标题与摘要 | 第六节消息面 |

逐日采集的固定步骤、连接器调用与字段映射见 [`DECISION_TDX_COLLECTION.md`](DECISION_TDX_COLLECTION.md)。

## 每日盘后流程

日常使用固定在「当日盘后出卡 → 次一交易日对答案」的节奏上。完整采集步骤见 [`DECISION_TDX_COLLECTION.md`](DECISION_TDX_COLLECTION.md)，本节只固定节奏、验收点与注意事项。

### 出卡（当日盘后）

1. 判定当日是否为交易日（采集文档步骤 0）；非交易日不出卡。
2. 按该文档步骤 1–5 执行：首跑决策卡拿到采集清单 → 通达信采集写入快照 → `tdx_snapshot` 自校验（`ok` 必须为 `true`，否则先修快照）→ 重跑出终稿。
3. 终稿为 `reports/decision/<trade-date>.md`，同源快照为 `data/decision/<trade-date>.json`。

时点与重跑规则：

- 只能在当日盘后运行。涨跌家数、板块榜是实时快照接口，给历史日期补跑会把运行当日的数据混入该日卡片，结论不可信。
- 建议 18:30 之后运行，数据源更新完毕再跑，宁晚勿早。
- 同一日期重跑会覆盖该日产物，属预期行为；试跑用 `--report-dir` / `--data-dir` 指向临时目录，避免覆盖正式产物。

### 对答案（次一交易日盘后）

用新卡核对上一交易日卡片第七节「次日观察点与失效条件」：

| 上一日卡的观察点 | 新卡核对位置 |
| --- | --- |
| 最高连板能否维持 N 板 | 第二节「情绪面板」· 最高连板 |
| 涨停家数能否维持 N 家 | 第二节「情绪面板」· 涨停家数 |
| 上涨家数能否继续多于下跌 | 第二节「情绪面板」· 涨跌家数 |
| 能否站稳 MA5（上一日卡中值） | 第三节「指数与量能」· 当日收盘 vs 上一日卡 MA5 |

失效条件逐条核对，触发即按卡片规则升降参与档。连续积累 5–10 个交易日后，可基于 `data/decision/*.json` 做一次预测准确度小结。

第三节「止跌迹象」同样要在次日对答案：只有观察点（站稳 MA5、量能放大、连板回升、深成指/创业板同步转正）被确认，止跌才算成立；未被确认即为失效形态，按原阶段处理。

### 定时任务（可选）

通达信采集只能经 Agent（MCP）通道，纯 Python 定时无法覆盖完整流程。纯 CLI 定时可得 akshare 单源卡：四个问题的结论不受影响，缺概念板块、涨停逻辑与消息面。要覆盖完整流程，用 WorkBuddy 定时任务：

- 频率：工作日收盘后（建议 18:30 起）
- 任务内容：确认交易日 → 按 [`DECISION_TDX_COLLECTION.md`](DECISION_TDX_COLLECTION.md) 步骤 0–5 出卡 → 与上一交易日卡片对答案 → 展示当日卡片

## 四个问题与规则来源

所有阈值集中在 `src/stock_review/decision/read_market_state.py` 顶部，判定为有序规则，先命中者优先。

| 问题 | 判定方式 | 规则来源 |
| --- | --- | --- |
| 市场情绪 | 涨停/跌停/炸板率/最高连板 + 全市场涨跌家数，按 冰点 → 退潮 → 主升 → 上升 → 混沌 顺序命中；另给 0–100 情绪温度作参考 | `stock-review.md` STEP 3 |
| 指数阶段 | 上证指数 5 日涨跌幅 + 10 日收盘箱体位置 + MA5/MA10，分为主升/下降/震荡；另附只用盘后事实的「止跌迹象」标记 | STEP 1.1 |
| 量能档位 | 两市 A 股成交额分 1 万亿以下 / 1 万亿–2 万亿 / 2 万亿以上，并提示环比急剧变化 | STEP 1.2 |
| 参与倾向 | 指数阶段 × 情绪阶段矩阵，输出 可参与 / 谨慎参与 / 不参与 / 待确认；情绪退潮期一律不参与（与仓位归零一致） | STEP 1.1 + STEP 3 |
| 买什么 | 板块内涨停家数聚集度（主证据）+ 概念/行业涨幅榜 + 连板梯队 + 板块领涨股 | STEP 4、STEP 6 |
| 买多少 | 量能档位基线 × 参与倾向 × 指数阶段修正，给出总仓位区间、单票上限（总资金口径）与标的上限 | STEP 1.1 / 1.2 推导 |

仓位区间是**框架推导建议，不是执行指令**；决策卡正文中每次都显式声明这一点。

### 分歧质量（结构）标记

情绪阶段只看当日横截面（涨停/跌停/炸板率/最高连板阈值），可能漏掉「高度断裂」：例如涨停家数未萎缩、情绪仍判上升期，但最高连板从 10 板骤降到 3 板。为覆盖这一盲点，决策卡增加一个**只用盘后已有事实**的结构标记：

| 信号 | 触发条件 | 阈值常量 |
| --- | --- | --- |
| 高标断板 | 最高连板较前一交易日下降 ≥ 3 板 | `DIVERGENCE_BOARD_DROP` |
| 封板质量转差 | 炸板率较前一交易日抬升 ≥ 10 个百分点 | `DIVERGENCE_BROKEN_RATE_RISE` |

- 任一信号触发 → 标记 **结构转弱**；两者都不触发 → **结构健康**；缺前一交易日最高连板 → **不可判定**。
- 结构标记**只作提示**，不改变情绪阶段、参与倾向与仓位区间的判定（三者仍由 STEP 1.1/1.2/3 规则决定）。
- 它在四问表的「当前市场情绪」结论后追加「｜结构转弱」，并在第二节情绪面板列出触发的信号。
- 完整分歧质量（分时、竞价、次日反馈）仍不在范围内，见「已知限制」5。

阈值集中在 `src/stock_review/decision/read_market_state.py` 顶部，判定函数为 `read_divergence_quality`。

### 指数止跌迹象标记

指数阶段用均线与箱体判**趋势方向**，判不出**短线是否被接住**：阴跌途中收盘仍在均线下方（阶段照判下降期），但当日可能已经出现低开高走与尾盘承接。为覆盖这一盲点，决策卡增加一个**只用盘后已有事实**的止跌标记：

| 条件 | 阈值常量 |
| --- | --- |
| 指数阶段为下降期或震荡期 | — |
| 收盘高于开盘（低开高走/收阳） | — |
| 收盘位于当日振幅 ≥ 60% 位置（收盘强度） | `CLOSE_STRENGTH_STRONG` |
| 处于 10 日箱体下沿 30% 以内（低位） | `STABILIZE_MAX_BOX_POSITION` |

- 四条全部满足 → 标记 **止跌迹象**；任一不满足 → **无止跌迹象**（并写明差在哪一条）；当日 K 线开/高/低缺失 → **不可判定**。
- 止跌标记**只作提示**，不改变指数阶段标签、参与倾向与仓位区间的判定（三者仍由 STEP 1.1/1.2/3 规则决定）。
- 触发时在第三节「指数阶段」后追加「｜止跌迹象」，并列出触发的信号（低开高走、盘中创新低后收回、处于箱体低位）。
- **止跌迹象不等于趋势反转**，也不判断「分歧能否修复」；是否成立需按第七节观察点在次日确认。同一形态在下跌途中可能反复出现又失效，属预期。
- 完整分歧质量（分时、竞价、次日反馈）仍不在范围内，见「已知限制」5。

阈值集中在 `src/stock_review/decision/read_market_state.py` 顶部，判定函数为 `_read_stabilization`（由 `read_market_stage` 调用）。

> 术语说明：本卡中的「收盘强度」指 `(收盘 - 最低) / (最高 - 最低)`，即收盘价在当日振幅中的位置，描述尾盘承接力度；它**不是下影线占比**。2026-10-13 之前的卡片曾把该值写作「当日下影占比」，属措辞错误，已修正。

## 已知限制

1. **概念板块受东财接口稳定性影响。** 环境代理阻断 `push2.eastmoney.com` 时，板块采集会退化到同花顺行业口径。此时若通达信快照提供 `board_quotes`，概念维度改由通达信板块行情补充；两者都没有才记入缺口。
2. **指数历史不含逐日成交额。** 指数日线接口不返回成交额，因此量能序列单独通过交易所每日概况采集，缺失的交易日保留空值并登记缺口。
3. **板块领涨股代码优先用通达信解析。** 板块字段只提供领涨股名称；名称未出现在当日涨停池时，先查通达信 `code_lookup`，仍无法确认才标记为待确认，不做猜测。
4. **情绪温度是参考指标**，用于横向比较当日强弱，不构成框架事实，也不进入参与倾向判定。
5. **完整分歧质量买点尚未纳入。** STEP 9 的十二模式需要分时、竞价与次日反馈证据，当前不在决策卡范围内；决策卡只提供只用盘后事实的「分歧质量（结构）」标记，不判断分歧能否修复。
6. **通达信快照由每交易日盘后任务自动采集。** 采集步骤固定在 [`DECISION_TDX_COLLECTION.md`](DECISION_TDX_COLLECTION.md)；当日未采集或连接器不可用时，决策卡仍照常产出并在第六节写明消息面缺口。
7. **量化阈值为自定口径，尚未校准。** 涨停/跌停家数、炸板率、连板高度、量能环比等判断阈值（如涨停 ≥ 50 与 ≥ 70、跌停 ≥ 15、萎缩 20%）在 `stock-review.md` 中没有对应原文，属决策卡自定口径；调整任何阈值都属于行为变更，须单独评审并记录理由。
8. **候选区标注覆盖度与截断。** 连板梯队、首板强势、炸板观察、板块领涨股各展示前 10 条并标注总数；涨停逻辑标注对连板梯队的覆盖率。展示条数受限不代表全量，「截断 / 未采」与「没有」在卡片中可区分。
9. **分歧质量（结构）阈值为自定口径。** 高标断板（≥3 板）与封板质量转差（炸板率抬升 ≥10 个百分点）属决策卡自定阈值，`stock-review.md` 无对应原文；调整属行为变更，须单独评审并记录理由。该标记只作提示，不进入情绪阶段/参与倾向/仓位的判定链。
10. **止跌迹象阈值为自定口径，且只判形态不判结论。** 「收盘强度 ≥ 60%」「处于 10 日箱体下沿 30% 以内」为决策卡自定阈值，`stock-review.md` 无对应原文；调整属行为变更，须单独评审并记录理由。该标记只用当日与近 10 日盘后事实，不含分时、竞价与次日反馈，因此**不能单独作为买点**，也不进入指数阶段/参与倾向/仓位的判定链；同一形态在下跌途中可能反复出现又失效。
11. **失效条件与阶段方向绑定。** 第七节的指数失效条件按当前阶段给出：已在下降期时，以「收盘跌破 10 日箱底」为下降延续信号；非下降期时，以「跌破 MA10」为转下降期信号。避免出现「条件早已成立、结论已是现状」的空条款。
